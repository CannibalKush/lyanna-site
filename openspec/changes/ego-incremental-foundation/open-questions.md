# Open Questions

These questions need decisions before implementation passes Phase 0.

## Player fantasy

1. Should the game focus on mastery, automation, discovery, or wealth?
2. Should the player control one person, a settlement, or an abstract account?
3. Should task choice feel active every few minutes or mostly idle?

## Progression

4. Should level rewards offer three choices or use a permanent skill tree?
5. Should specializations lock permanently for a run?
6. Should graph nodes grant tasks, effects, automation, or all three?
7. How large should the first graph be?

## Economy

8. Should materials have fixed value or changing market value?
9. Should silver buy power, convenience, or access?
10. Should insight come from XP, discovery, or deliberate research tasks?
11. Should legacy grant vertical power, horizontal options, or both?

## Automation

12. Should automation require resource maintenance?
13. Should routines fail when conditions change?
14. Should automation capacity be scarce?
15. Should the player optimize routines or only select priorities?

## Prestige

16. What event makes a reset feel earned?
17. What does the player lose?
18. What does the player keep?
19. Should each prestige offer a new branch or improve the same branch?

## Community

20. Should the first community feature be builds, challenges, or leaderboards?
21. Should players trade with each other, or only with simulated markets?
22. Should guilds share progress or only share goals?
23. What identity and moderation tools are required before public interaction?

## Security

24. Is offline progress excluded from all rankings?
25. Is ranked play a separate mode with separate saves?
26. Does the first ranked mode need a server-authoritative simulation?
27. What data may the server retain?
28. What anti-abuse response is acceptable for suspicious runs?

## Presentation

29. Should the camera feel like a clay tablet, a shrine, a city, or a living landscape?
30. Should the pixel style use crisp hard pixels or a softer illustrated texture?
31. Which feedback deserves the strongest celebration: discovery, level-up, or system unlock?
32. Should audio enter the first prototype, or follow visual polish?
33. Should Creative Commons assets support the prototype, or should we create original placeholder art first?
34. Are we comfortable recording asset attribution inside the repository?

## Decisions recorded

- Community features are deferred.
- Future leaderboards require server authority and fixed challenge rules.
- The first systems are Gathering, Meditation, Incantation, and Bartering.
- The visual style is ancient, esoteric, pixel-art-inspired, and responsive.
- Early play is active.
- Later play adds queues and automation.
- System unlocks should feel like revelations.
- The first prototype should use a living clay-tablet visual metaphor.

## Recommended defaults

Use these defaults if no decision exists:

- One player character.
- Active task selection first.
- Three reward choices at major levels.
- Four currency families.
- Small acyclic graph.
- Repeat automation before conditional automation.
- Prestige after a meaningful account milestone.
- Fixed challenge leaderboards before open-ended rankings.
- Offline mode excluded from ranked play.
- No direct player chat in the first community release.
